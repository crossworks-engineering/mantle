## Pages

Rich documents — the place for writing that has structure: a proposal, a runbook,
meeting notes, a spec. Headings, callouts, tables, columns, to-do lists,
diagrams.

Pages differ from Notes by intent rather than size. A note is something you jot;
a page is something you'd hand to someone. Pages can link to each other, mention
people and files, and be **shared** as a read-only public link when someone
outside needs to read one.

Body edits are kept as a **draft** until you commit them, so a page someone else
is reading never changes under them mid-sentence.

## Assistant

- "Write this up as a page called Site Handover."
- "Add a section at the end about the generator service."
- "What did the handover page say about the pump?"
- "Share the handover page and give me the link."

The important habit: when the assistant edits a page, the change lands in the
**draft**, not the live page. You'll see it flagged in the editor and decide
whether to publish. That is deliberate — it means you can ask for a big rewrite
without gambling the version other people are reading.

Whole-page deletes and overwriting a live page are held back from the everyday
assistant on purpose, so an ambiguous instruction can't quietly destroy a
document.

## Technical

A page's body is a **ProseMirror document** stored as JSON on the node, with the
uncommitted draft alongside it in a separate column. The editor is TipTap; the
public share view renders the same document server-side rather than shipping the
editor to a stranger.

Everything a page can contain is expressible as **markdown** — that's a design
rule, not a coincidence. It means a page can be written by a human in an editor,
generated by the assistant as plain text, and read back as legible source
without a lossy conversion in either direction. Diagrams are Mermaid for the
same reason.

For the brain, the page is chunked and embedded so passages surface in search
and in the assistant's retrieval, with the summary carried on the node itself.
When the assistant edits blocks rather than replacing the body, it addresses
them by stable **block ids** — so an insert into a long document doesn't rewrite
the whole thing, and two edits to different sections don't collide.

The tool groups mirror the risk: light draft edits and page creation are
everyday, full authoring is a specialist's, sharing is its own switch, and
destructive operations sit apart from all of them.
