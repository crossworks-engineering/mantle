# 0.209.0 (2026-07-28)

*(Backfilled from the release commits; includes the v0.208.0 work, which was
never tagged separately.)*

**Bulk table writes, honest progress trails, and the note-editing gap closed**,
follow-through on a production table-update audit that watched an agent burn 6
delegation retries, 128 capped calls and ~18 minutes appending 101 rows one at
a time.

## Added

- **`table_rows_add`** (v0.208.0): bulk append of up to 200 rows in ONE atomic
  batch (one draft rev). Row-id echo elided above 20 rows; unknown columns
  reported once across the batch. Tool descriptions + the `table_authoring`
  skill now steer bulk appends here (`table_from_text` is explicitly
  CREATE-only, the cap-guidance loophole that left stray imported tables is
  closed).
- **`table_rows_upsert`**: bulk merge into an existing table keyed on chosen
  column(s): new keys append, changed rows patch only the given cells,
  identical rows count as unchanged, ambiguous keys are skipped + reported;
  all-or-nothing validation. The one-call form of "refresh this table from an
  export".
- **`note_update`** builtin (replace or append), closes the responder's "no
  way to extend the Daily Work Log" gap. `note_delete` deliberately stays out.
- **`traces-reap`** cron-schedulable sweep (all owners, dry-run default) +
  a stray-imported-tables audit check on `/debug/integrity`.

## Fixed

- Stage labels name the tool + subject ("Updating table row 'X'…") instead of
  "Working on it…"; spill pages say "Reading more results…".
- A fully-guard-blocked batch (≥3 calls) forces the final answer immediately
  instead of paying for more blocked rounds.
- The trace reaper stamps `duration_ms` NULL, no more fabricated 41-hour runs.
- Ledger (the tables agent) gets the Pages-sized tool budget (100/40) via
  manifest `memoryConfig`, force-synced on reconcile.
