# 0.207.0 (2026-07-27)

**Themes are now generated, every text colour correct by construction.** The
~40 tweakcn presets were imported artwork with no contrast contract; only 4 of
42 were self-consistent, and four separate bugs last release were all the same
structural fact: a token used for a job it was never derived for. This release
ends the class: `themes.css` is a build artifact, and every text token is
SOLVED at build time against the surfaces it must be legible on.

## Added

### The theme generator (`packages/web-ui/themes/`)

`seeds.mjs` is the authored source, one record per theme: surfaces, fills,
decor and text *anchors*, extracted from the hand-maintained CSS and
normalised to hex. `generate.mjs` derives the full scale: keep each anchor's
hue and chroma, move lightness the minimum that clears AA **measured on the
emitted 8-bit hex**. An authored value that already passes ships
byte-for-byte unchanged; a broken fill/foreground pair moves whichever side
shifts least (the v0.206.7 accent repair, done mechanically). `pnpm
themes:build` regenerates; a drift test fails CI if the artifacts disagree
with the seeds. New docs: `docs/themes.md`; visual harness:
`themes/preview.html`.

### Semantic roles: success, warning, info

First-class beside `destructive`, fill + `-foreground` + `-ink` each, one
global hue per role, chroma borrowed from the theme (mono stays quiet,
cyberpunk loud), lightness solved per theme, hue-deconflicted from orange-ish
destructives. Callouts, diff/edited highlights, status pills, runs/sandboxes
state maps and the paused/waiting banners now say what they mean instead of
borrowing chart tokens.

### The code palette: `--code-keyword/string/number/title/variable`

Syntax highlighting had been painting with chart tokens, function names
rendered at **1.02:1** (invisible) on `claude` dark. The code palette is
ink-contract derived: keyword anchors on `primary-ink` (the brand hue survives
into code), the rest are fixed semantic hues, all AA on every neutral surface
in every theme. `json-tree` in dev-tools rides the same tokens.

### `chart-1..5` are charts again

Generated categorical ramps, five distinguishable hues anchored on the brand
(achromatic themes get a lightness ramp), 3:1 against the chart surfaces.
Pinnacle's authored brand ramp is pinned by a seed override. All
chart-as-text consumers were migrated off.

## Changed

- **The full contrast matrix is now asserted for EVERY theme**, light and
  dark, on-fill pairs, inks × surfaces, rings, plus generator drift,
  solver behaviour and palette distinguishability (8,400+ checks). The
  pinnacle-only scoping is gone because the generator makes the matrix
  satisfiable everywhere.
- **Ink audit hardened** (closes its computed-value blind spot): a
  `color: color-mix(…)`/literal declaration now FAILS unless allowlisted with
  a reason; silence is how `.prose-accent h3` shipped below AA on 52 of 164
  surfaces. That h3 now uses `primary-ink`. `KNOWN_UNSAFE` is **empty** and
  stays shrink-only.
- **Lint**: `pair-fill-foreground` and `use-ink-for-text` cover the new roles
  from day one (`text-success` et al. are build errors; use the `-ink`).
- Palette movement at the switchover, measured (`themes:report`): 647 of
  2,788 pre-existing values, ~400 of them the chart ramps; on-fill
  foregrounds moved in only ~8 blocks at ΔE ≤ 0.05. Fills deepened only
  where their own declared pair was broken.

## Removed

- **`retro-arcade` and `northern-lights`**: structurally self-contradicting
  palettes (retro-arcade dark declared its own body text on its own muted
  fill at 2.01:1; no derivation can rescue an authored pair). A stored
  selection falls back cleanly to the baseline theme.

## Deploy

**Tag-only. No migrations, no compose change, no new env.**

⚠ **Roll the client stack**: the change is almost entirely the owner UI's
stylesheet, and `docker compose up -d` does not roll `mantle_client_web`.

```
docker compose -f docker-compose.client.yml --project-directory . pull
docker compose -f docker-compose.client.yml --project-directory . up -d --wait
docker ps    # confirm mantle_client_web carries the new tag
```

After rolling, verify against the served artifact: fetch the live stylesheet
and check `--code-keyword` exists and `--success` is present in `:root`.
