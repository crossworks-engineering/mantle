# 0.205.7 (2026-07-27)

**The `/` menu's selected row stops bleaching itself out.** In the Pages editor,
the highlighted block in the slash menu (and in the `@` mention menu) rendered
its description line and its icon tile against the wrong surface, so on themes
with a light or saturated accent, the description vanished into the highlight.

## Fixed

### Selected rows now derive every child from `accent-foreground`

The row itself was correct (`bg-accent text-accent-foreground`) but two
children opted out of that pairing:

- the description/kind line hardcoded `text-muted-foreground`, a token paired
  with `--muted`, not `--accent`;
- the icon tile hardcoded `bg-background`, so on the selected row an
  `accent-foreground` icon sat on the `background` fill, a pairing no theme
  makes any promise about, and a dark block punched into a bright highlight.

Both now switch with selection: the tile becomes a tint of the row's own ink
(`bg-accent-foreground/10`, `border-accent-foreground/25`) and the description
becomes `text-accent-foreground`.

**27 of the ~84 theme/mode combinations were affected**: that is, ones where
`muted-foreground` on `accent` falls below 3:1. The worst were effectively
invisible: sunset-horizon dark at **1.06:1**, soft-pop dark at 1.11:1,
midnight-bloom and northern-lights dark at 1.18:1. All now render at the theme's
own declared accent pairing.

Note this fixes the *markup*, not the palettes: a handful of imported tweakcn
presets declare an `accent`/`accent-foreground` pair that is itself weak
(midnight-bloom 2.36:1, bubblegum 2.54:1, catppuccin light 2.79:1). Those rows
are now legible but still below AA, a theme-level defect to address separately.

Files: `client/web/components/page-editor/slash-menu.tsx`,
`client/web/components/page-editor/mention-list.tsx`. The style guide's rule is
§2, "pair every fill with its OWN `-foreground`".

## Upgrading

Nothing to do, CSS classes only, no migrations, no config.
