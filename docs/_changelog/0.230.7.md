# 0.230.7 (2026-08-08)

Drawings stopped being second-class. They now arrive in Word documents as
pictures, they come back in the theme you drew them in, and you can pan around
one without opening it for editing. Alongside that, reading a page no longer
means editing it: the preview grew the outline, the reading width, focus mode
and Share, so the whole read-and-send loop happens without the editor.

## Drawings reach Word

A page exported to `.docx` used to print `[drawing: alt]` where the picture
should be. Markdown, HTML, share links and PDF all showed the real thing; Word
was the one degraded surface, because it embeds only PNG, JPEG, GIF and BMP and
a drawing's stored snapshot is SVG.

The export now rasterizes the snapshot on its way into the document. It is a
screenshot of the same sheet the PDF export prints, not a second render of the
scene, so the picture in your Word file is the same snapshot every other
surface serves and cannot drift from it. It goes in at twice the resolution so
it survives being printed, and lays out at the width of the body column.

Nothing is stored. If the drawing has never been committed, or the browser
sidecar is unavailable, the export still succeeds with the old labelled
placeholder rather than failing.

The assistant's own `export_node` tool still writes the placeholder. It runs in
processes that have no browser to rasterize with, and giving it one is a
separate piece of work.

## A drawing comes back in the theme you drew it in

Draw something in dark mode, commit it, and the preview showed it light. Not a
bug in the snapshot: Excalidraw's dark mode is a filter over the canvas rather
than a change to the colours, so a drawing made in the dark stores dark strokes
on a white canvas and shows you the inverse. The snapshot is deliberately
captured light, because it is also served to share links, PDF and Word, and it
must not depend on which theme its author happened to have open.

What was missing is that the rule never reached the app's own surfaces. Now the
`/draw` previews and drawings embedded in a page apply the same filter the
canvas does, so what you see matches what you drew. Nothing stored or exported
changes, and share links, print and both exports keep their light rendition,
having no app theme to follow.

A drawing containing a pasted photo keeps its light rendition everywhere, since
inverting a flat image would turn the photo into a negative.

If you want a genuinely dark drawing, one that travels to share links and
exports too, set the canvas background to a dark colour and pick light stroke
colours. Then the darkness is part of the drawing rather than a property of the
viewer.

## Look at a drawing without editing it

The preview showed a flat image, so a diagram bigger than the pane could only
be read by opening it for editing. That is a strange thing to have to do to
look at something, and it puts an accidental edit one stray click away.

A new button in the preview header swaps the image for the real canvas in
read-only mode: pan, zoom, no editing, no draft. It mounts only when you ask
for it, so browsing the list still costs one image rather than the whole
editor.

## Read and share a page without opening it

Focus mode and Share were both available only inside the editor, which put
reading and sending behind an edit you did not want to make. Both now sit in
the Pages and Draw preview headers.

Focus mode on a list screen also puts the list away, not just the app chrome.
Hiding the frame while leaving the list beside the content would have missed
the point. The list is only hidden, so your search text, scroll position and
page number are all still there when you come back out. Reading one page after
another keeps focus mode on; going to a different screen ends it.

The preview also gained the two things that make a page readable: the **page
index** down the left, jumping to any heading, and the **narrow / wide**
control. The preview used to ignore a page's stored width entirely, so a page
written wide came back narrow to read. It honours it now, and the toggle writes
the same field the editor does.

One difference from sharing inside the editor: a link minted from the preview
serves the last committed version, because a list screen has no draft to
publish first. The "Draft, uncommitted" badge beside the title tells you when
that is behind what you last typed.
