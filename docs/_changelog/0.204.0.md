# 0.204.0 — 2026-07-26

The **team workspace reads inline**. Selecting a shared page, table, note,
task, event, file, folder or formula in `/team` (and in the hub) renders the
content in the reader pane itself — no iframe, no *"This item opens on the
brain's own site"* card, no bounce to a new tab. Underneath sits the bug that
made that card appear in the first place: **every same-origin deployment
believed it was running split**.

If you read one section, read [Fixed](#fixed).

## Fixed

### Every same-origin brain thought it was split

**Affects every deployment on the default one-domain layout — which is every
production deployment.**

Since the member carve, the client decided "am I cross-origin from the server?"
by testing `runtimeApiBase() !== ''`. But the client app *always* needs an
absolute `MANTLE_SERVER_ORIGIN` — its own server-side fetches can't be relative
— so the installer sets it unconditionally, **including on the default
same-origin shape** (one domain, path-routed, `Caddyfile.same-origin`). On
every such box the runtime base was set *and equal to the page origin*, and the
predicate read "set" as "elsewhere". Consequences, all live:

- The `/team` reader pane refused to render — members got the redirect card on
  the very deployments where an inline reader needed no cross-origin machinery
  at all.
- The token gate minted **bearer-mode** sessions (`localStorage`, no cookie),
  so members held no cookie for the `/s` surfaces that authenticate by one.
- The hub sent every briefing open on a top-level SSO detour that same-origin
  navigation never needed.

The predicate is now [`isCrossOrigin()`](../../packages/web-ui/src/runtime-env.ts)
— a real origin comparison (`new URL(base).origin !== window.location.origin`)
— and every member-surface call site moved onto it. Unit-tested against the
exact shape that hid the bug: base configured **and** equal.

Tested at the e2e layer too, because this class of bug was **invisible to both
existing topology projects**: the suite ran "no base configured" and "base on
another origin", never "base configured, same origin" — the shape every real
box is in. `team-reader.spec` now pins it: content inline, zero iframes.

### Members who already hold a bearer get the cookie back, silently

Sessions minted while the mis-detection was live hold only the localStorage
bearer — valid, but the `/s` subresources an inline reader loads (page images,
downloads, table rows, the app bundle) authenticate by cookie. `POST
/api/team/sso` now accepts an **absent** `next`: verify the bearer exactly as
before (signature + per-request membership liveness), set the cookie
first-party, answer **204** — no redirect, no token re-entry.
`upgradeTeamCookie()` fires once per page load as a **memoized awaitable**; the
reader awaits it so the first open can't race the `Set-Cookie`. A present-but-
invalid `next` is still 403 — absent means upgrade, malformed never does.

## Added

### The inline reader

`GET /s/<token>/view` returns the share as JSON — same resolution, same
authorization as the `/s` HTML page (active token, and for team mode a live
team session via cookie **or** bearer), same uniform 404 for
invalid/revoked tokens. Two kinds are server-shaped on purpose:

- **Pages arrive as pre-rendered sanitized HTML + outline.**
  [`renderPageDoc`](../../server/web/lib/render-page-doc.ts) never moves
  client-side — escaping stays on the server, and KaTeX + lowlight stay out of
  the client bundle.
- **Folders arrive as a listing** for the requested `?p=`, validated against
  the shared root per request; the reader navigates sub-folders in place.

[`ShareReader`](../../client/web/components/team-workspace/share-reader.tsx)
mounts the same presenter components the `/s` surface renders — they moved to
`@mantle/web-ui/share`, so there is **one** implementation of "what a shared
table looks like" consumed by both apps. Apps keep their `AppSandbox` iframe:
that one is an *execution* sandbox for third-party code (opaque origin,
`allow-scripts` only), not a reading surface.

The share surface stays the only content door — `/view` is a sub-path of `/s`
with the share token as the sole capability; nothing reads content by node id.

### The hub reads inline too

The hub's briefing/app-card reader swaps its `/s` iframe for the same
`ShareReader`, and — with the predicate fixed — same-origin members get the
in-hub reader again instead of top-level SSO navigations.

## Changed

- The `/s` sub-paths a client-origin page may call cross-origin grew from the
  three app brokers to five: `view` and `rows` join
  `bundle`/`tool-broker`/`db-broker` (bearer-authed by
  `resolveShareVisitorFromRequest`, CORS-scoped by the same regex). The
  `/s/<token>` HTML page and the remaining sub-paths stay cookie-only with no
  CORS headers at all.
- A **genuinely** cross-origin client (a real `app.<domain>` split) keeps
  exactly the old behavior: shares open top-level through the SSO handoff —
  inline reading there would strand cookie-authenticated subresources.
- A share revoked after the list loaded now reads *"This item is no longer
  shared"* instead of offering a retry that cannot succeed.

## Testing

- `team-reader.spec` (new): a shared page reads inline with **no iframe** on
  the same-origin project; the fallback card on split.
- `team-bearer.spec`: same-origin now *expects* the silent upgrade cookie;
  cookie-freedom is asserted only where it's the contract — split.
- Two harness fixes so the hermetic suite runs on a clean machine:
  `run-local.sh` exports `MANTLE_MASTER_KEY` explicitly (it used to leak in
  from a `server/web/.env.local` that fresh worktrees and boxes don't have),
  and `MANTLE_RATE_LIMIT_SCALE` (×10 on the throwaway stack only) stops the
  two topology projects' back-to-back auth exchanges from tripping the 8/min
  team-auth cap — scaled, not disabled, so a runaway spec still hits a wall.
- Full net at release: **31 passed / 0 failed**, both topology projects.

## Upgrading

Nothing to do — no migrations, no compose changes, no config changes.
Members re-authenticate nothing: bearer sessions upgrade to cookies silently
on their next `/team` or hub load.
