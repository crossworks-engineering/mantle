# 0.203.0 (2026-07-25)

The **formulas workbench**: `/formulas` becomes a place you can author a
calculation, not only read one. Plus two pre-existing bugs found while building
it that had nothing to do with formulas and everything to do with every brain
on the split client/server layout, **a dead share link and a dead toggle**.

If you read one section, read [Fixed](#fixed).

## Added

### A calling contract for every formula

`signatureOf(spec)` ([formula-signature.ts](../../packages/content/src/formula-signature.ts))
answers the question that comes *before* "what is the number": **what must I
hand it?** Per evaluable target it returns what the target produces and every
input, unit, required-vs-defaulted, and for a lookup key or a rating its legal
values plus the classification's criteria prose.

It is a **static mirror** of the evaluator's resolution ladder, not a second
opinion, if the two disagree, the evaluator is right and the signature is the
bug. Two properties fall out of being static rather than a dry run:

- **It sees every branch.** A dry run with placeholder values reports the inputs
  of whichever piecewise case happened to match, so a form built from it loses
  fields the moment a pressure crosses a threshold. Branch needs are unioned;
  `branches` carries the per-case breakdown.
- **It cannot fail on arithmetic.** No divide-by-zero, no lookup miss, asking
  what a formula needs must never itself error.

It also rolls `unverified` **up**: a piecewise carries none of its own while
branching entirely on a from-memory equation, and "may I rely on this number"
is the question that matters.

Surfaced on `formula_get`'s `targets`, on `GET /api/formulas/[id]` as
`signature`, and as a `Callable:` section in `formulaToText`, so the embedding
captures *capability* ("can it work out a release rate from pressure and
temperature?") rather than only text. Never persisted; computed on read.

### The editor

A guided form and a YAML source view over one draft
([formula-editor.tsx](../../client/web/app/\(app\)/formulas/formula-editor.tsx)).
Two things make it more than a settings form:

- **The validation rail is live and complete.** `parseFormulaSpec`,
  `checkLookupCoverage` and `checkDimensions` run *in the browser* on every
  keystroke, the same pure functions the server runs on save, never a
  reimplementation that can drift. They report every problem at once, which is
  why the validator was written to collect rather than throw. The three
  findings stay visually separate because they mean different things: a parse
  error is a malformed spec, a dimension issue is usually a dropped term, and a
  coverage gap is a fact about the *source* that is not the author's to fix.
- **YAML is a first-class view, not an export.** Criteria prose and
  transcription notes are multi-line English, which JSON turns into unreadable
  escaped strings. Form and source round-trip through one draft; the parser
  lives in `client/web` so `@mantle/content` stays parser-free.

Templates cover blank / single equation / piecewise / lookup / full model, plus
an **annotated showcase** whose comments carry what no form label conveys: why a
table is rows and not an `IF()` chain, why `latex` is never parsed, what
`unverified` is for.

### Sharing a formula as a live calculator

`formula` joins `SHAREABLE_TYPES`, and the `/s` page is deliberately **split**:

- **Server-rendered, no JavaScript**: equations (KaTeX server-side,
  `trust: false` pinned), lookup tables, rating criteria, transcription notes,
  and all the warnings. A shared engineering calculation that renders *without*
  its `unverified` notice is worse than one that does not render at all, so
  nothing load-bearing depends on a bundle arriving.
- **A client island**: the live calculator, built from the signature embedded
  in the page payload. It renders the derivation, not just the number.

`POST /s/[token]/evaluate` is a safe public compute surface because
`evaluateSpec` is pure: no model, no network, no DB write, no filesystem, and a
hand-written parser over a fixed grammar with no path to a global scope. Capped
anyway, 60/min per IP, 200 input symbols, 1000 chars per value, 512KB body.

> **Team-mode caveat.** `formula` is not in `TEAM_WORKSPACE_TYPES` (a deliberate
> whitelist), so a team-mode formula share does not list in the /team workspace
>, send the link directly. The share control's hint says so. Hub listing is
> deferred work.

### Euler, the mathematician

No agent was *responsible* for formulas. The persona could evaluate one, but
transcribing a calculation out of a standard (the actual bottleneck) belonged
to nobody, and authoring a spec is a different skill from running one.

`mathematician` (display name **Euler**) ships through the system manifest,
which is the point: the boot reconcile auto-provisions it with delegation wired
on every brain's next upgrade. Its kit is deliberate, `formulas` + `calculator`
to work, `memory-core` to read an ingested standard, `files` to open an uploaded
PDF, because a transcriber that cannot open its source is useless. **Not**
`formulas-admin`: deleting a calculation model stays a deliberate human act.
Temperature 0.2; the failure mode here is a plausible *invented* equation, not
a dull one.

Two skills, split by audience:

- **`formula_use`** (persona + team responder): the fast path for "calculate
  X": read the input list off the contract rather than inferring it, **name the
  units** when asking (a value supplied in the wrong unit is the commonest way
  one of these goes quietly wrong), and quote the trace when answering.
- **`formula_authoring`** (the specialist): the spec shape and the
  transcription ethic: cite what you actually read, `unverified` on anything
  from memory, record the source's defects in `notes` rather than silently
  correcting them, `edition` always.

Team members get a new `formulas-eval` group, find, read, compute; never
author.

### Five instructional formulas

Ideal gas density, Reynolds number, Darcy–Weisbach head loss, orifice
discharge, pump power ([formula-seed.ts](../../packages/content/src/formula-seed.ts)).
The bank stays owner-derived, a brain fills with the calculations its owner's
work needs, so what ships is a primer, chosen so that between the five every
construct appears at least once, including exactly one deliberately
`unverified` equation so the warning can be *seen* rather than described.

They double as the **regression suite**: each carries worked examples with
expected values, so a change that quietly breaks exponentiation or lookup
matching fails in CI instead of on a live assessment. Writing them, the
dimension checker caught two real defects in the drafts that reading had not,
fluid properties hard-coded as bare numbers (producing 1/length instead of a
velocity), and a chained symbol reading as dimensionless because the checker
learns units from `variables` only.

Add them from the `/formulas` empty state or the New-formula dialog. Idempotent,
tagged `instructional` so the set can be cleared as a group, and deliberately
**out** of the boot reconcile: if you read them and delete them, an upgrade that
silently restored them would overrule a decision you already made.

### The read path finally shows what the backend computes

Four gaps, all the same shape, the API returned a finding and the UI dropped
it. `unverified` badges (the docs promised "renders as a warning everywhere";
it rendered nowhere), the dimension-issues card, `specErrors`, and the
`standard`/`tag` filters that the API had always accepted. The evaluator now
builds its fields from the signature, so only the chosen target's inputs appear
and a rating is a picker carrying the source's own criteria.

## Fixed

### Every copied share link pointed at the wrong host

**Affects every share, of every type, on the split client/server layout.**

`ShareControl` built the link as `window.location.origin + share.path`. That was
correct while Mantle was one app, but since the member carve the owner UI and
the server are two origins, and `/s/…` is the **server's** surface. The copied
URL therefore pointed at the client, which has no `/s` route: it 404'd or
bounced to `/login` depending on the deployment.

Measured against a running stack:

| URL | Result |
|---|---|
| `client-origin/s/<token>` (what got copied) | **307** → login |
| `server-origin/s/<token>` (where `/s` lives) | **200** |

`serverUrl()` ([runtime-env.ts](../../packages/web-ui/src/runtime-env.ts))
resolves against the runtime `serverOrigin` that `/env.js` already publishes for
exactly this purpose, falling back to the API base then the current origin, so
the same-origin monolith is untouched. The Shared-links registry had the
identical bug and the same fix.

Tested, because this class of bug is **invisible in a same-origin setup**: it
only appears once the two origins differ, which no same-origin test exercises.

### Every Switch and Checkbox in the owner UI had no checked state

**Also fleet-wide, and also nothing to do with formulas**: it surfaced as "the
share toggle doesn't switch on".

`client/web/app/globals.css` `@import`s the shared theme layer but had no
`@source` for `packages/web-ui/src`. An `@import` pulls in CSS; it does **not**
add source files to scan, and Tailwind v4's auto-detection stops at the app's
own root. So every utility used *only* inside the shared component package
emitted no CSS at all, including the Switch's `data-[state=checked]:bg-primary`
track and its `:translate-x-4` thumb, and the Checkbox's checked styles. The
toggles were functionally fine and visually frozen.

Verified against the compiled stylesheet the browser was actually served:
`translate-x-4` appeared **zero** times, and the only `data-[state=checked]`
rules present traced to files inside `client/web`. Adding the `@source` line
took the stylesheet from **312KB → 363KB**: so a good deal more than those two
components had been silently under-styled.

`server/web/app/globals.css` has carried the line all along; it was missed when
the owner UI moved to `client/web` in the member carve.

### Formula-specific fixes from the post-implementation audit

- **The editor destroyed legitimate `null` lookup cells.** `isScalar` allows a
  null cell and an `onMiss: 'null'` table legitimately carries them, but the
  draft's `prune` dropped null like any other absence, so a *valid* stored spec
  came back from the editor failing validation on a "missing result" it never
  had, with save locked. Pruning now treats everything under a `rows` key as
  table data.
- **A non-parsing stored spec rendered a blank pane.** Every detail section
  indexes into arrays the validator guarantees, so the first `.map` threw. It
  now names the problems and shows the stored JSON.
- **Three divergent string→scalar coercers** (owner evaluator, editor, public
  calculator) unified into `parseInputText`. `'1e-5'` was a number in two and a
  string in the third, which arithmetic forgives and strict-equality lookup
  keys do not.
- **Template/seed spec-id collisions** made "Add 5 example formulas" silently
  skip a real entry, since the seeder detects presence by `spec.id`. Two found;
  a disjointness test keeps them apart.
- Seed presence checking no longer stops at the first 500 formulas; the
  filtered-empty list no longer offers the seed action as though the collection
  were empty; a cleared display title now resets to the spec name instead of
  silently keeping the old one.

## Changed

- `ApiError` carries the parsed error body, so an endpoint that validates
  all-at-once (formulas, tables) can show its whole `errors` array instead of
  being collapsed to the first line.
- The editor defers validation off the keystroke path, the mathjs dimension
  pass on a large spec is the difference between typing and wading.
- `refsIn` in [table-formula.ts](../../packages/content/src/table-formula.ts):
  static symbol extraction on the one tokenizer, so a brace inside a string
  literal stays text.

## Upgrading

Nothing to do, no migrations. Two notes:

1. **Euler auto-provisions** on the first boot after upgrade (the reconcile runs
   once per `APP_VERSION`, production only). Confirm at **Settings → Config**
   that no drift is reported.
2. **Existing formulas keep their old embeddings** until their next edit. The
   `Callable:` section is what makes capability retrieval work, so after
   upgrading a brain with formulas already in it, re-save each spec unchanged
   (`formula_update`) to re-extract. Deliberate, rather than a backfill job,
   see [docs/formulas.md](../formulas.md) §4a.
