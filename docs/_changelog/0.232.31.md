# 0.232.31 (2026-08-22)

The files workspace learned to show you your files instead of describing them.

## Thumbnails

An image in the file list used to be a name and an icon; seeing the picture
meant opening it. The file route now serves a thumbnail variant: a bounded
512-pixel JPEG, rendered once per content version and cached on disk, so a
folder of phone photos browses at tile weight instead of original weight.

The renderer reuses machinery already on board — the same canvas engine that
rasterizes PDFs for OCR, and the same HEIC conversion the vision pipeline
uses, so iPhone photos thumbnail like everything else with no new
dependencies. Thumbnails live beside the files root, outside the watched
tree, keyed by content hash: overwrite a file and the stale preview simply
stops being referenced; delete a file and its previews are reaped with it.

Anything that cannot be thumbnailed — a PDF, a zip, a corrupt image, an
absurdly large one — answers "no thumbnail" and the client shows the type
icon. That path is a fallback, never an error.

## A real details view, and a grid

The file table's columns now sort: name, type, size, modified — click to
sort, click again to flip. Size and modified default to biggest-first and
newest-first, because that is what anyone clicking them wants. A new Type
column says "Word document" rather than making you decode an extension.

Next to it, a thumbnail grid view: images as pictures, everything else as
its tinted type icon, with the name-only badge carried over from the
indexing switch. The list/grid choice sticks across visits.
