# 0.205.4 — 2026-07-26

## Fixed

### Every admin can set the brand — and they all set the same one

Mantle is multi-trusted-admin by design: a handful of peers, no privilege
tiers. Contacts are the trust boundary; **users** are not ranked. But brand
preferences didn't behave that way.

The routes never blocked a second user — `getOwnerOr401` admits any signed-in
user — so their edits were *accepted* and written to **their own** preferences
row. Almost nothing brand-facing reads that row: `/api/appearance` (the
before-paint stamp on every origin), the `/s` share and `/print` surfaces and
`/team` all resolve the **anchor** owner's row. The result was silent no-ops
and split-brain rather than an honest refusal:

- a theme change repainted that user's shell but not the first-paint stamp,
  `/team`, or any share;
- a site or peer name showed only in that user's own header;
- **a logo upload produced a broken image** — `/api/shell` reported the
  version from their row while `/api/appearance/logo` served bytes from the
  anchor's.

Preferences now split by what they *describe*. **Brain-level** fields — site
name, peer name, colour theme, the two display fonts, the logo, and the
brain's purpose/archetype (`BRAIN_PREFERENCE_KEYS`) — live on one shared
record: any signed-in user reads and writes it, and the change is visible to
everyone and every member surface immediately. **Personal** fields — timezone,
locale, avatar, reminder routing, streaming/thinking preferences — stay on the
user's own row, because two admins should differ freely. Light/dark remains a
per-browser choice, as before.

Single-user brains are unaffected (one row, one query). The split is pinned by
a test, since its failure mode is invisible: a mis-filed field lands in a row
nothing reads and the edit simply does nothing.

## Upgrading

Nothing to do — no migrations. On a brain with more than one user account,
brand fields now resolve from the anchor owner's row; any brand values a
secondary user saved into their own row were never rendered anywhere and are
ignored (re-set them once from any account).
