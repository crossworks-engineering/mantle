# 0.212.0 (2026-07-29)

**Your model, provider and prompt choices now survive upgrades, on every
agent.** Decision: the system manifest owns an agent's definition at birth,
the operator owns it afterwards.

## Changed

### The boot reconcile no longer overwrites prompt/model on specialists

- `syncSpecialistDefs` previously force-synced every manifest specialist's
  systemPrompt + model + params back to the manifest on each version-bump,
  silently reverting operator model switches (and restoring `model` without
  `provider`, which could strand an incoherent route). It now syncs **only
  params/memoryConfig tuning** (max_iterations, limits; `delegate_to` still
  preserved verbatim). Prompt, model, provider and API key are
  **operator-owned on every agent**: the persona already was.
- **First-time manifesting is unchanged**: onboarding seeds the full manifest
  definition, and a newly shipped specialist is still auto-provisioned with
  its manifest prompt/model/route. Shipped prompt/model improvements reach
  existing brains only via the operator's own pull, Studio's
  reset-to-default.
- `/settings/config` drift: a specialist model difference is now surfaced as
  informational (like the prompt), not weighted as medium drift; it's a
  legitimate customisation, not a problem.
- The v0.211.2 revert warnings are updated to match: the "system" badge on
  the Models tab now reads as provenance ("ships with Mantle; your route and
  prompt survive upgrades"), the picker's revert warning is gone, and the
  Agents editor hint points at Studio reset-to-default instead of warning
  about reversion.
- `lib/system-manifest/CLAUDE.md` propagation table updated.
