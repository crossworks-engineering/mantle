# 0.207.1 — 2026-07-28

**The theme-generator audit pass.** An adversarial audit of v0.207.0 re-derived
its claims from the shipped bytes: contrast maths verified against canonical
WCAG references, surfaces byte-faithful across all 82 blocks (the only ΔE >0
is sub-8-bit rounding of the one oklch-notation theme), worst hue drift of any
solved token 1.6°, zero chroma sacrifices. Two real findings, both fixed:

## Fixed

- **The solver could fail silently.** `solveText` reports infeasibility (a
  surface set that demands light AND dark text at once) but the generator
  emitted the value anyway, leaving CI's contrast tests to catch it three
  artifacts downstream. `mustSolve` now aborts `themes:build` with an error
  naming the anchor and surfaces. Covered by a test with an engineered
  mid-luminance surface pair.
- **`boring-avatar`'s pre-mount fallback palette was stale** — still the old
  mono-indigo clean-slate ramp, causing a brief wrong-palette flash on the
  default theme. Now the generated categorical ramp.

## Documented (measured, deliberate — docs/themes.md "Deliberate limits")

`secondary` requires its own foreground (15/82 blocks below AA for plain
`foreground`, zero live call sites, lint guards the provable cases);
pinnacle's light brand ramp really is below 3:1 (the seed override's point);
roles may coincide with the brand hue (twitter info ≈ primary) while the
safety-critical distinctions stay enforced; user colour marks remain 3:1
decoration; cross-platform drift determinism is empirical with a named
mitigation if it ever breaks.

## Deploy

Tag-only; no urgency — the guard is build-time and the fallback is a
