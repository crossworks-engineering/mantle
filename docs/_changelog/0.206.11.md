# 0.206.11 (2026-07-27)

**Rules that were written down are now rules that run.** No new feature surface
in this release, by design. A robustness plan converted seven prose conventions
into executable ones, and the theming system gained the token it was missing.

The through-line: both real bugs found on 2026-07-27 were in finished, shipped
features that had quietly stopped being correct, and in both cases a written
rule already existed. Prose works exactly as long as the reader is diligent.

## Changed

### Text is no longer the fill colour

`--primary` and `--destructive` are tuned to sit **behind** their own
`-foreground`, which makes them dark and saturated. Used as **text** on a
neutral surface they were frequently illegible: measured across the presets,
47 pairs below 2:1, a Delete label at 1.05:1, and one theme rendering its text
and its surface as the same hex.

One token cannot do both jobs. As a fill it wants to be dark enough for light
`-foreground` text; as ink on a dark surface it wants to be light. In dark mode
those are irreconcilable, a repaint that moved the fill left ~25% of themes
with **no solution at all**, and where it did succeed it re-authored the
palette (retro-arcade magenta → maroon, candyland pink → dusty rose).

So the ink is now its own token:

- **`text-primary-ink` / `text-destructive-ink`**: 172 tokens, one pair per
  theme block. Lightness moved in OKLab only, so each ink stays in its fill's
  colour family. 52 of 172 are identical to their fill (those palettes already
  cleared AA). Zero infeasible.
- **The fills are untouched.** Every `bg-primary` / `bg-destructive` button
  renders exactly as its theme author drew it. Only text moved. 329 call sites
  migrated.
- `mantle/use-ink-for-text` fails the build on a bare `text-primary` /
  `text-destructive`, so it cannot regress.

`packages/app-build/src/kit.ts` is deliberately **not** migrated; it is a
string mirror compiled inside the app sandbox, a separate CSS build.

### Eleven palettes brought to AA

The accent pair (the fill behind selected rows, menu items and ⌘K results)
failed its own `accent-foreground` on eleven theme/mode combinations, worst
2.36:1. All eleven now clear 4.5:1, again by moving only lightness and only
whichever of the two tokens shifts less, so each theme keeps its polarity and
character (max ΔL 0.16). Four picker swatches moved with their accent.

## Added

### Guards that fire instead of documents that ask

- **Theme contrast is now asserted for every theme**, not just Pinnacle:
  the accent pair, both ink tokens against all five surfaces, and picker-swatch
  integrity, across 42 themes × 2 modes. The colour parser handles `oklch()`
  and `hsl()`, not just hex, so the oklch-authored baseline is covered too.
- **`mantle/pair-fill-foreground`**: catches `bg-X … text-Y` where Y is not
  X's foreground. Deliberately narrow: ink is resolved per *variant state*, so
  the codebase's dominant and correct `text-muted-foreground hover:bg-accent
  hover:text-accent-foreground` idiom is not flagged. It found exactly two
  violations repo-wide, both real, both fixed.
- **pg client/server invariant**: the Dockerfile's `postgresql-client-N`, both
  composes' `POSTGRES_IMAGE_TAG`, and `resolvePgDump`'s candidate ordering must
  agree. `pg_dump` refuses a server newer than itself, so a mismatch aborts
  every backup; the previous half-fix went undetected for two days.
- **Duplicate migration numbers fail the build**, along with a journal `idx`
  that disagrees with its filename, the state a mis-resolved `_journal.json`
  merge produces, which the existing uniqueness check cannot see.

### `pnpm status`

Derived truth in one command: local vs origin, unpushed commits, every worktree
with uncommitted changes, branches not in `main` across all remotes, and each
box's running version from `/api/version`. It also asks the other dev machine
what it is sitting on, flagging anything dirty and older than a day as
`STRANDED`, a finished fix once sat invisible in a worktree on another machine
for two days.

Fleet hosts are **not** in the repo: set `MANTLE_FLEET` / `MANTLE_PEERS`, or an
untracked `.mantle-fleet.json` (see `.mantle-fleet.example.json`).

## Fixed

- Two icon buttons in the pages tree turned their fill to `accent` on hover
  while the icon stayed muted.
- `eslint .` no longer walks a leftover pre-v0.202 `apps/` tree. It was
  producing 752 errors from a directory that is not part of the repo, which
  meant the pre-push gate failed for a non-reason, and a gate that cries wolf
  gets bypassed.

## Deploy

**Tag-only. No migrations, no compose change, no new env.**

⚠ **Roll the client stack.** 130 of the 156 changed files are `client/`; this
release is almost entirely the owner UI, and `docker compose up -d` does **not**
roll `mantle_client_web`. Rolling only the server ships nothing visible while
reporting the new version, because `/api/version` is the server.

```
docker compose -f docker-compose.client.yml --project-directory . pull
docker compose -f docker-compose.client.yml --project-directory . up -d --wait
docker ps    # confirm mantle_client_web carries the new tag
```
