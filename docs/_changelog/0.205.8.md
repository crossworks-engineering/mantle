# 0.205.8 (2026-07-27)

**The docs sidebar opens quiet.** `/docs` used to unfold every collection and
every folder on arrival, 334 rows of tree before you'd clicked anything. Now
each section starts closed, and the Changelog sits at the bottom where you'd go
looking for it.

## Changed

### Sections are collapsed by default

The nav tracked *collapsed* ids in a set that started empty, so "nothing
collapsed" meant "everything open". That's now inverted: it tracks **expanded**
ids, and an empty set means everything is closed. First paint is **3 rows
instead of 334**.

Deep links are unaffected, navigating to a doc still auto-expands its
collection and every ancestor folder, so the current page is always revealed.
That effect now adds ancestors to the expanded set instead of removing them from
the collapsed one.

### The Changelog moved to the bottom

Collections sorted user-authored first, then `system`, alphabetical within each
group, which put **Changelog** *above* **System docs**, since C sorts before S.
It now ranks dead last explicitly: User Guide → System docs → Changelog. It's the
largest collection (185 files) and the one you visit deliberately, so it no
longer sits between the guide and the developer docs.

## Notes

Doc **content** was already lazy and still is: the nav payload carries file
*paths* only (~10 KB for 331 files across all collections, one request, 30s
stale time), and a document's markdown is fetched per-doc from
`/api/docs/reader/doc` by a react-query keyed on `(collection, path)`; nothing
is read off the server's disk until you click a doc. No change was needed there.

Files: `client/web/app/(app)/docs/docs-nav.tsx`, `server/web/lib/docs-reader.ts`.

## Upgrading

Nothing to do, no migrations, no config.
