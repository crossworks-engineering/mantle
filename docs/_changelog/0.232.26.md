# 0.232.26 (2026-08-21)

A brain now watches its own health without being asked, on every box, and the
manifest finally knows what a heartbeat is.

## The brain-health heartbeat ships by default

Once a week, jittered by up to six hours and respecting quiet hours, your brain
checks two things about itself: how close its corpus is to the split policy, and
whether retrieval quality has drifted. If neither has moved, it says nothing.
Silence is the expected result. A weekly message you can ignore is worse than no
message at all.

This existed before, but only on one machine. It was installed by a script
someone had to know about and run by hand, so it lived on exactly the brain of
the person who wrote it. Nothing shipped it anywhere else, and nothing could:
the manifest describes agents, skills, tools and workers, and had no concept of
a heartbeat at all.

The clearest evidence of the gap was already sitting in the manifest. A
`brain-health` tool group had been there from the start, and its description
read "grant to the agent that runs the brain-health heartbeat". No agent was
granted it. No such heartbeat existed. It was an instruction addressed to
nobody. The persona now holds that group, and a test fails the build if a
default heartbeat ever needs a group the persona lacks.

New brains get the heartbeat at onboarding. Existing brains get it on the next
boot, through the same reconcile that keeps skills and specialists current.

## Installed once, then left alone

Every other part of the manifest converges: on each upgrade, reconcile rewrites
skill bodies and specialist definitions back to what the product intends.
Heartbeats deliberately do not work that way.

A heartbeat row holds things the product has no business overwriting. Whether it
is paused is a decision you made. Its schedule and quiet hours may be your
tuning, not ours. And `next_fire_at` is live state: rewriting it on every boot
would mean a box that redeploys weekly never reaches its own fire time, and the
heartbeat would appear to work while never running once.

So the rule is create-only. A missing heartbeat is installed; an existing one is
never touched. The single exception is a skill reference that no longer resolves,
which is repointed, because the fire loop pauses a heartbeat whose skill has gone
and a rename on our side would otherwise kill it quietly.

Pause it in the UI and it stays paused through every upgrade. `/debug/integrity`
now reports heartbeat health, and treats paused as a decision rather than a
fault.

## An unmeasured brain is not a failing brain

The retrieval eval scores search against a set of known-good question-and-answer
pairs. That set has to be written per brain, because each case names real pages
by id, so no set can ship with the product.

The eval used to treat a missing set as an error. Combined with a heartbeat whose
rule was "tell the user if the eval failed", that meant a new brain would report
a problem every single week, forever, about a check its owner had never set up.
The eval now reports that it was skipped, and the heartbeat treats skipped as
what it is: nothing to say. Quality is unmeasured, not degraded. The distinction
is the difference between a useful alert and a weekly false alarm.

## Also

The hand-run `seed:brain-health` script is gone. The manifest does its job now,
and a second way to install the same thing is a second thing to drift.
