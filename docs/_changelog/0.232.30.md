# 0.232.30 (2026-08-22)

Files can now live in the workspace without living in the brain.

## Name-only indexing

Some files you store because the workspace is a good place to keep and share
them, not because you want an AI reading them: a photo gallery, temporary
files, the audio clips the transcriber leaves behind. Until now there was no
middle ground — everything uploaded was read, summarised, chunked into
searchable passages, and mined for facts.

Flip a folder to **name-only** and every file under it keeps the plumbing but
loses the reading. The files stay stored, shareable, renameable, and findable
by what they _are_ — name, type, folder, tags — but their content is never
opened: no passages, no facts, no content summary. The index entry says so in
as many words, so an assistant quoting it will tell you it has not read the
file rather than bluffing.

The switch inherits. Mark a folder and its whole subtree follows; any child
folder or single file can override in either direction. Files added to a
name-only folder later are covered from the moment they arrive.

Flipping is honest in both directions. Turning content indexing **off** also
removes the passages that were already indexed — otherwise search would keep
serving the very content you just un-indexed — and costs no AI calls at all.
Turning it back **on** re-reads every affected file through the normal
extraction queue, which is real model spend in proportion to the file count;
that is what you asked for, and the folder toggle tells you how many files it
queued. Flipping a switch to the value it already has does nothing.

One known limit, stated rather than hidden: facts extracted _before_ a flip
stay in the knowledge graph until curation touches them. The flip stops
future reading and removes passages; it does not rewrite history.

## Where the switch lives

- In the app: a toggle in the folder header (showing inherited state as
  such), a one-click override in the file editor, and a "name only" badge on
  every affected file row.
- For agents: `file_set_indexing` and `folder_set_indexing`, in the `files`
  tool group. Listings and file details now report the mode, so an agent can
  see why a content search misses a file instead of concluding it lost it.
- Over MCP: `file_upload` and `folder_create` accept `indexing: 'metadata'`,
  so a Claude session can create a store-and-share area in one call.

A fresh install changes nothing: every file still indexes fully until someone
says otherwise.
