# 0.214.0 (2026-07-30)

**House style: one setting that governs every agent's prose.** Settings →
Profile gains a free-text box for the owner's writing conventions (the
motivating rule: "never use em dashes"). The text is appended to every
composed system prompt as a `## House style` block, so it reaches chat
replies, Telegram, heartbeats, team/forum turns, and, the part no existing
mechanism covered, the delegated specialists that author pages and tables.

## Added

### The `houseStyle` preference

- Brain-level (`BRAIN_PREFERENCE_KEYS`): it describes how this brain writes,
  not how one login works, so every admin edits the one record and every
  agent reads it from the anchor row.
- Free text rather than per-rule checkboxes; the first rule anyone wants is
  "no em dashes", the second is "don't say 'delve'", and a boolean per taste
  doesn't scale. Capped at 2000 chars (`HOUSE_STYLE_MAX`); it rides in the
  cached prefix of every turn on every agent.
- Unset emits **nothing**: the composed prompt is byte-identical to a brain
  that predates the feature, so prompt caches are undisturbed until the
  moment an owner actually sets a style.

### Injection at the single composition seam

- `composeSystemPromptWithSkills` gains an optional third argument and places
  the block **after** the skill blocks: the owner's rule outranks shipped
  writing guidance (`chat_writing`, `rich_writing`) by recency, deliberately.
- All composition paths route through that seam and now pass the preference:
  the shared responder assembly (`assembleResponderTurn`, web, mobile,
  Telegram, team, forum, sim/`respond_as_agent`, durable-runner resume),
  delegated specialists (`invoke-agent`, which loads the owner's preferences
  itself, soft-failing so a preferences blip never sinks a delegation),
  heartbeat firing, the Studio sandbox, and Studio's composed-prompt preview
  (a preview that omitted it would be exactly the hidden prompt Studio exists
  to prevent).
- The block ships with a verbatim-material carve-out: it governs prose the
  agent authors, never quoted text, retrieved content, code, or a document
  being reproduced or edited verbatim. An agent "fixing" source material to
  satisfy a style preference is a correctness bug, not a style fix.

## Why not a persona note or a skill

Persona notes are injected by `renderPersonaBlock` on the responder turn
only; a delegated child's prompt is composed from its own `skillSlugs` and
never sees them, so a style note set on the assistant never reached the
Pages specialist, precisely the agent that writes documents. A skill would
reach the specialists but has to be attached per agent and lives as content
rather than a setting. The preference + seam covers every path from one
place.
