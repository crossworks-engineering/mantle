# 0.213.0 (2026-07-29)

**CLI sandboxes are part of the system on fresh installs.**

## Changed

### Installer: sandboxes default ON for a fresh box

- `scripts/install.sh` now treats the sandbox stack as standard equipment on a
  genuinely fresh install (same freshness rule as the generated DB secrets,
  no postgres data dir yet): it adds the `sandboxes` compose profile to
  `COMPOSE_PROFILES`, generates `SANDBOXD_TOKEN` (never rotated on re-run),
  points `MANTLE_SANDBOXES_HOST_DIR` at `<data-dir>/sandboxes` (resolved
  host-absolute), and **pre-pulls the sandbox base image** so the coder
  agent's first `sandbox_create` doesn't stall on a multi-hundred-MB
  download. Opt out with `--no-sandboxes`.
- **Existing boxes are never flipped implicitly**: an installer re-run keeps
  whatever the box has. `--sandboxes` performs the same idempotent enable on
  an existing box; `--no-sandboxes` disables (stops sandboxd; sandbox
  `/files` dirs untouched). Once enabled, the profile lives in `.env`, so
  every later update keeps sandboxd running with no further work.

## Fixed

- Installer `upsert` no longer dies under `set -e` when the key being
  replaced is the only line in `.env` (latent since the helper was written;
  unreachable in practice but now hardened, found by the new logic's dry-run
  tests).

## Docs

- `docs/sandboxes.md` enabling section, `.env.example`, and the compose
  comment updated for the fresh-install default.
