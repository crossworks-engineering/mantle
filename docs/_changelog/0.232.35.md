# 0.232.35 (2026-08-22)

An audit of the file-manager work found one real leak and closed it, plus
three smaller gaps.

## The name-only promise now holds against keyword search too

Search in Mantle has three legs: passages, vectors, and plain keyword
matching. Flipping a file to name-only cleaned the first two but not the
third — the extracted text stayed cached on the record, and the keyword index
is built over the whole record, so a search for words _inside_ the file
still found it. The name-only summary even said "content is not searchable"
while keyword search quietly disproved it.

The flip now strips the cached text as well. The file itself is untouched —
the bytes on disk are the source of truth, and flipping back to full re-reads
them from there.

## Copies keep their name-only flag

Copying a name-only file — or a whole name-only gallery — produced copies
without the flag, which meant the copy got fully indexed: the exact opposite
of what the owner said about that content, silently, at up to 200 files of
model spend. Flags and tags now travel with every copy, and a copied folder's
flag is set before its files arrive, so they index correctly from the first
moment.

The same audit caught an ordering bug in folder copies: a file sitting
directly in the copied folder could be processed before its destination
folder existed, failing the copy. Folders now strictly precede their files.

## Also

- The integrity screen counted a disabled heartbeat skill as present; the
  fire loop requires it enabled, so that green was false. It now checks
  enabled.
- MCP clients (Claude Desktop, Claude Code) get the six file-manager verbs —
  move, copy, and the indexing switch for files and folders — bridged from
  the same implementations the in-app agents run, not rewritten. The repo's
  own duplicate-tool guard caught the first draft of this doing it the wrong
  way, which is exactly what that guard is for.
