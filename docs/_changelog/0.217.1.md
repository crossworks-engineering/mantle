# 0.217.1 (2026-07-31)

**Microsoft Project plans become queryable tables.** Save a plan as XML from
Project (File → Save As → XML) and upload it: Mantle reads it into three typed
grids (Tasks, Resources, Assignments) with durations as numbers, dependencies
resolved to task names, and your own custom fields as columns. Ask it what has
no float, what is off track, or how many hours sit in a work area, and the
answer comes from the plan rather than from a filename.

This release also closes a hole that had nothing to do with Project: **`.xml`
files were completely unreadable**, indexed by their filename alone. Every XML
upload now gets its text extracted.

## Added

### Project plan import

- **Three tabs per plan.** Tasks (with WBS, outline level, dates, work, cost,
  baseline, slack and predecessors), Resources (rates, groups, cost centres) and
  Assignments (who is on what, and how much of it).
- **Detected by content, not by extension.** `.xml` is a container, so a plan is
  recognised by its root element and namespace. Any other XML is left alone and
  simply indexed as text. A file that looks like a plan but can't be parsed
  falls back to text too; the worst case is a searchable document, never
  nothing.
- **Durations are numbers**, so they can be summed and compared. Hours
  throughout, plus days where a plan is normally discussed in days, converted
  using the plan's own working calendar rather than an assumed 8-hour day.
- **Dependencies read as names.** `Predecessors` shows
  `Gather Data (FS+15d)` alongside a `Predecessor UIDs` column that keeps the
  exact references.
- **Your custom fields become columns**: but only the ones actually in use. One
  real plan defined 35 and populated 3; the other 32 were untouched template
  boilerplate and are omitted rather than shown as 32 empty columns.
- **Unassigned work is labelled**, not blank.

### A table can carry a caveat

Tables now have a **description** that a reader (human or assistant) sees
*before* querying. Imported plans use it to state the roll-up rule (below).
Existing tables are unaffected.

## Fixes

- **`.xml` files were unreadable.** Not in any parser route, so an upload was
  indexed by its filename and nothing else, the same silent gap `.mpp` had, for
  a plainly readable format. Now extracted like any other document.
- **Upload limit raised 25 MB → 64 MB.** A 1094-task plan came in at 25.8 MB,
  which is 98.5% of the old ceiling and not a large plan.
- **Mini-apps logged console errors and lost their maths fonts.** The app
  sandbox allowed the host stylesheet but refused the webfonts that stylesheet
  declares, so anything rendering formulas fell back to system fonts.
- **Three screens could fail against a read-only or partially-provisioned
  database**, Activity, Maintenance, and Runners each performed a tidy-up write
  or read an optional subsystem before showing you anything, and failed the
  whole page when that was refused. They now show what they can.

## Notes

**Summary rows already include their children.** A Project plan's roll-up rows
carry the totals of everything beneath them, so adding up every row counts the
same work once per outline level, on a deep plan that overstates by ~5×, and it
looks entirely plausible. Every imported plan carries a `Summary` column and
says so in its description; filter with `WHERE "Summary"=0` for any total. The
assistant reads that caveat before it writes a query.

**Timezones are not invented.** Project stores wall-clock times with no zone, so
they are kept exactly as written rather than shifted into UTC.

**Large Office files and the new upload limit.** Tika's parser heap was sized
against the old 25 MB ceiling. A 64 MB PowerPoint or Word file can now be
accepted at upload and still exhaust it during parsing; the sign is an empty
text extraction. On a box with 8 GB or more, raise Tika to `-Xmx2g`.

**On v0.217.0.** That tag exists but was cut from a branch that had not caught up
with `main`, so its image is missing four fixes that were already released,
including the Activity and Runners read-path guards. **Do not deploy it.**
v0.217.1 is the same work, reconciled. The duplicate guards were resolved in
`main`'s favour; the one this release adds is `/api/debug/maintenance`, which
tidied up stale rows with an UPDATE before listing them and so failed the same
way against a database that will not accept writes.
