# 0.213.4 (2026-07-29)

## Fixed

- **App-DB and table-workbook backups were silently producing 0-byte archives
  on every box.** `backup-app-dbs.ts` and `backup-table-dbs.ts` did all their
  work correctly and printed their summary, then never exited: the pooled
  Postgres client (`postgres()`, cached on `globalThis`) holds open sockets, so
  once the snapshot was done the process still sat in the event loop forever.
  `db-dump.sh` runs `set -e; …snapshot…; tar -czf - .` inside a _single_
  `docker exec`, so the `tar` was never reached and the redirect left a 0-byte
  `.tgz`. Nothing looked wrong, the scripts' own failure branch can't fire
  (nothing failed, the command never returned) and the Postgres dump succeeds,
  so a backup run reported success while quietly omitting every app database
  and table workbook. Found on a fleet roll: the last good app-db archive on
  one box was four days old.

  New `closeDb()` in `@mantle/db` ends the pool; both scripts call it in a
  `finally` and set `process.exitCode` instead of calling `process.exit()`, so
  the summary still flushes and the documented 0/1/2 exit codes survive.
  Measured on a live brain: both now exit in ~1.5s (previously killed at
  timeout), and the full `snapshot && tar` pipeline produces a valid archive.

  Any future one-shot script that touches `db` needs the same `closeDb()`,
  long-lived servers must not call it.
