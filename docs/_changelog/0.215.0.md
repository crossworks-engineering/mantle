# 0.215.0 (2026-07-30)

**Mantle Desktop.** The owner UI leaves the browser: a new Electron app
(`client/desktop`) carries the full web client inside a native shell. First
run asks for your brain's URL, then the normal login, and because the shell
is a *native client* in the same trust stance as the mobile companion, it
works against every existing box with **zero server-side CORS setup**.

## Added

### The desktop shell (`client/desktop`)

- **Connect screen** with the mobile companion's probe-before-save pattern:
  the URL is validated against `GET /api/version` before anything persists.
  Saved brains show their server version, with skew against the bundled UI
  surfaced rather than hidden.
- **One session partition per brain**: tokens, cookies and caches are
  isolated per profile, so multiple brains keep separate logins and a
  relaunch lands straight back in the last one used.
- **Embedded UI, no dev server**: the standalone `next build` of
  `client/web` runs as a `utilityProcess` on a loopback port. The port is
  deliberately *sticky* (persisted per install); localStorage is
  origin-scoped, so a wandering port would log every profile out.
- **Native-parity CORS fencing**, scoped to the configured brain origin
  only: the shell drops its outgoing `Origin` (native clients send none,
  the server's gate already skips CORS for them) and supplies the response
  headers its own embedded Chromium insists on. Nothing about the server's
  browser-facing posture changes, and no box needs `MANTLE_API_CORS_ORIGINS`
  for the desktop app.
- **Token vault**: the bearer at rest is encrypted with the OS keychain
  (Electron `safeStorage`, Keychain / DPAPI / libsecret; 0600-file fallback
  where no keychain exists). An existing localStorage bearer migrates in on
  first read and the plaintext is scrubbed.
- **Desktop integration**: `mantle://` deep links (e.g. `mantle://n/<id>`)
  across cold start and running activation; OS notifications for assistant
  replies while the window is hidden; a tray with open / switch brain /
  quit; auto-update from GitHub releases that downloads in the background,
  notifies once, and installs on quit, never a surprise restart.
- **Packaging + CI**: electron-builder targets (Linux AppImage/deb, macOS
  dmg/zip, Windows nsis); `.github/workflows/desktop.yml` builds all three
  on the same `v*` tags as the images and uploads installers to the **draft**
  GitHub release; publishing stays a human act. macOS artifacts are
  unsigned until Apple credentials land in CI, which also means no macOS
  self-update yet.

### Shared-code seams

- `@mantle/web-ui/desktop-shell`, single owner of the `window.mantleDesktop`
  type; everything feature-detects, so browsers are byte-for-byte untouched.
- `client/web` gains a `DesktopBridge` component (assistant outbound pings →
  OS notifications, hidden-window only) and an opt-in standalone build
  (`MANTLE_STANDALONE=1`) that normal image builds never take.

## Fixed

- **Login-bounce deadlock** (any split client, not just desktop): an abrupt
  shutdown could drop the unflushed presence cookie while localStorage kept
  the bearer, leaving the login page bouncing against the middleware forever
, valid token, no way in. The bounce now re-asserts presence before
  navigating, so the state self-heals; the shell additionally flushes the
  cookie store on window close.
- **Image builds no longer download Electron**: `client/desktop` joining the
  workspace would have pulled the ~100 MB binary into every server/client
  image build; the Dockerfile install now skips it.
