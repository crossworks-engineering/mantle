# 0.206.0 — 2026-07-27

**One responder, every screen.** Your assistant keeps its conversation
everywhere — no surface switches you to a specialist anymore — and when it
delegates, you now watch the specialist work by name instead of staring at a
frozen "Delegating…". Plus dark-mode logos, agents that can finish a page
edit, and an updater that finally updates itself.

## Changed

### No surface pre-selects an agent

The API Console's docked Toolsmith panel was the last chat that switched you
to a specialist — a separate transcript that knew nothing of what you and
your responder had been discussing. It's gone, along with the whole
per-surface assist machinery (`/api/assist/*`, `/api/profile/assist-agent`,
the per-surface agent preferences and picker). The console's **Assist** button
opens the global assistant, which keeps its context and hands tool-building
to Toolsmith itself via delegation; the button pulses "Working…" while a turn
runs, and the console's Agent-tools list refreshes when the turn settles.

### Delegation shows its work

While a specialist works inside your turn, its live steps are attributed by
name — "Pages · Editing the page…", "Toolsmith · Testing the API…" — in the
streaming thought trail. The stage line (shown when live streaming is off)
now follows the running specialist instead of freezing on "Delegating to…",
and no longer goes dark two minutes into a long delegation: an older turn
keeps narrating as long as its specialist shows recent activity, and stays
quiet otherwise — the stale-trace guard, re-keyed on actual activity.

## Added

### A dark-mode logo

Settings → Appearance → Logo now takes an optional dark-mode variant next to
the base logo, each with its own preview strip rendered on its own theme —
the dark strip shows the real dark header even while you browse in light
mode. Headers swap purely in CSS, and the fallback is dark → base →
wordmark, so one universal logo never needs two uploads. Uploading the same
file as both variants is handled safely (they share one stored object).

### Agents can finish a page edit

`page_commit` publishes the draft an agent wrote — carrying the draft
revision it read, so an editor autosave landing mid-commit surfaces as a
conflict instead of silently publishing a stale draft — and
`page_discard_draft` abandons a bad one, mirroring the table tools. Leaving
the draft for your review in the editor remains the default; publishing is
also what makes the new body searchable.

## Fixed

### The updater now updates itself

The bind-mounted `updater.sh` was the one release-owned file nothing
refreshed: a stale copy rolled the server stack, reported ok, and silently
skipped the client stack — found on every box in the fleet on 2026-07-26.
It now installs the canonical script from the target image at the end of a
successful update and re-enters it, with a syntax gate so a bad script can
never crash-loop the sidecar. `/settings/updates` shows when a box's script
is stale or hand-edited instead of leaving the gap silent.

### Update runs stopped reporting the previous run's outcome

A healthy update could briefly flash the *previous* run's failure (or
success) while the sidecar picked the request up. The window is closed on
both ends — the sidecar claims the run in its first statement, and the page
ignores terminal statuses that still carry the prior run's timestamp.

### Rolling no longer takes the site down for ~2 minutes

The updater recreated caddy behind the web app's health gate on every roll,
so the public site (including the update progress you were watching) went
dark for the health-start window. Caddy now converges separately without the
gate: unchanged, it never stops serving; changed, it restarts in about a
second.

### Owner sign-in is cookie-based again on one-domain deployments

The same "`apiBase` configured ⇒ cross-origin" mis-detection fixed for team
members in v0.204 also had every owner on a default deployment signing in
bearer-only — and every `<img>` asset URL carrying a signed token into
browser history for no reason. Owners now get cookie sessions same-origin;
existing bearer-only sessions upgrade themselves silently on the next page
load (short-lived cookie, renewed continuously, so revoking a device still
bites within a week).

### The audit log says "Login"

The column and filter formerly labelled "User" — on the one screen where the
distinction between logins *is* the point — plus the first-run screen and
the self-hosting doc's stale "one brain, one account" claim.

## Groundwork (shipped dark)

Member-to-member team notifications — "can you let Deepthi know?" — ship
their data path in this release (migration `0138`, the notify tools, the
live-membership gate) but are granted to **no agent** yet: until the
recipient's dash inbox lands, a responder claiming "I've let her know" about
an invisible notification would be worse than today's honest "I can't reach
her".
