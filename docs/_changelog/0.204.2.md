# 0.204.2 — 2026-07-26

## Added

### A brand logo — upload once, both headers carry it

**Settings → Appearance → Logo**: upload an SVG, PNG, JPEG or WebP (≤512KB)
and it replaces the siteName wordmark in the owner header *and* the `/team`
member header — fixed height, width free, `object-contain`, never distorted;
bounded by the header bar exactly like the peer name. The settings card
previews at real header height on the header gradient, and the live header
updates the moment the upload lands (shared `['shell']` query invalidation —
no reload). Remove restores the font wordmark.

Under the hood, deliberately boring in the right ways:

- Bytes land **content-addressed** in object storage (`putContent`) — never a
  user-visible, user-deletable file node — and the anchor owner's prefs store
  only a validated `{logoKey, logoType}` pointer (jsonb, **no migration**).
  The sha doubles as the cache-busting version, so the public serve route
  caches `immutable`.
- Serving is `GET /api/appearance/logo` — public like the rest of
  `/api/appearance` (a brand is what every share link already renders).
- **SVG is validated, then sandboxed anyway.** The upload identifies the type
  from the BYTES (magic numbers; an `<svg` root for svg — the browser's
  claimed type is never trusted) and hard-rejects SVGs carrying active
  content (`<script`, event handlers, `javascript:` hrefs, `foreignObject`,
  remote `<use>`). The serve route adds CSP (`default-src 'none'`) + nosniff
  as the second layer. Validators are unit-tested
  ([logo-validation.ts](../../server/web/lib/logo-validation.ts)).
