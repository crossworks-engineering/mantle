# 0.205.5 — 2026-07-26

**Mantle isn't multi-user — it's one brain with one or more logins.** That's
the model, and two things didn't reflect it.

## Fixed

### An added login was walked into the first-run wizard

Onboarding completion was keyed per login. A second login therefore had no
`onboardedAt`, no `onboardingStep`, and owned no agents — so the shell's gate
sent it to `/onboarding` on a fully provisioned brain. Worse than the
annoyance: **finishing that wizard would have provisioned a second agent set
under that login's id** — a parallel half-brain sharing none of the first's
work.

Onboarding is now brain-level (it joins `BRAIN_PREFERENCE_KEYS`), and the
gate's legacy "already has an enabled agent" fallback checks the **brain's**
agents rather than the caller's — a login owns none of its own and would have
failed that test forever. Add a login today and it lands straight in the app.

## Changed

### Settings → Users is now Settings → **Logins**

The screen manages ways *into* the one brain, not separate users with separate
data — the code already said so in a comment; the copy now says it too.
"Add user" → **Add login**; the anchor row reads *"The anchor login. The brain
is keyed to it, so it can't be deleted."*; an added row reads *"Another way
into this brain. Same brain, same data, same settings — actions are recorded
under this identity."*

The route (`/settings/users`), the API and the database are unchanged —
this is language, not plumbing, so existing links keep working.

## Upgrading

Nothing to do — no migrations. On a brain that already has more than one
login, the extra logins stop being offered onboarding on their next load.
