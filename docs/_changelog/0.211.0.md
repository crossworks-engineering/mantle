# 0.211.0 — 2026-07-29

**Bulk model switching — the Models tab on Settings → Agents.** Moving a fleet
of agents to a new model used to mean opening each editor in turn. The agents
screen now has two tabs: **Agents** (the master-detail editor, unchanged) and
**Models**, a full-width matrix of every agent's provider, model and API key
with staged bulk editing.

## Added

### The Models tab

- **The matrix**: one row per agent (persona, specialists, operator agents —
  disabled ones included, badged), showing the primary chat route: provider,
  model, and which stored API key it uses.
- **Compact picker**: *Change* opens a provider → model → API key dialog built
  from the same parts as the agent form — the live per-provider model catalogue
  (`/api/models`), keys filtered to the selected provider, the same
  not-in-catalog and unwired-provider warnings.
- **Staged, not saved**: picking stages the change in memory. The row renders
  **before → after** (old value struck through, key shown when it changes),
  with a per-row ✕ to un-stage. The staged diff *is* the confirmation surface —
  no extra dialog on apply.
- **"Last selected" one-click**: after any pick, every other row grows a
  quick-apply button labelled with that set — switching N agents is one full
  pick plus N−1 clicks.
- **Apply all**: a sticky footer bar ("N changes staged · Apply all · Discard
  all") PATCHes each agent sequentially; failures keep their staged entry and
  show the API error inline on the row, successes clear with a ✓, and a toast
  summarises the run.
- **Scope guard**: only the primary chat triple `{provider, model, apiKeyId}`
  is ever written. Backup routes, params, prompts, tool grants, and TTS pins
  are untouched — they remain the agent editor's job.
- The tab is URL-driven (`/settings/agents?tab=models`), so it's linkable;
  staged changes are deliberately memory-only and discarded on leaving.
